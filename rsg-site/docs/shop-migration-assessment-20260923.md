# 能量商店、課程音檔與金流遷移評估

2026-09-23；僅進行公開頁面與既有新站程式的唯讀調查。沒有修改商店、會員、金流、DNS 或執行付款。以下工期為初估，尚未取得商店後台完整盤點。

## 結論

課程音檔確實在能量商店內。若希望完全離開 WordPress，需要重建商品訂單、會員登入、學習存取權限，以及金流通知流程。Cloudflare 可以作為新系統部署平台，但不能把原有 WooCommerce / LearnPress 的 PHP 外掛直接放進目前 Astro / Workers 網站。

建議先保留現有金流供應商，將金流介接獨立封裝。是否改藍新，等既有商店的付款方式、物流、發票、合約費率及退款需求盤點後決定；沒有必要為了搬離 WordPress 同時更換金流。

## 若全部接回 Cloudflare

建議架構為 Workers 處理訂單、登入與金流回呼，D1 保存訂單與會員權限，私有 R2 保存音檔。播放時先驗證學員權限與到期日，再發短效存取網址；不能把付費音檔直接放進公開靜態目錄。金流使用代收業者付款頁，不自行保存信用卡資料。

管理端至少需要商品編輯、訂單查詢、出貨狀態與課程授權調整。會員除了登入，還要找回帳號、舊帳號接續、已購課程和有效期限。舊密碼不得以明文遷移；是否可驗證舊雜湊或需重設密碼，待帳號資料盤點。

付款成功必須依伺服器收到並驗證的通知更新訂單，核對金額及訂單編號，且重複通知不可重複發放權限。綠界官方區分 ReturnURL 後端通知與付款後前端導回，並有檢查碼規格；不是只做一顆付款按鈕。[綠界產生訂單文件](https://developers.ecpay.com.tw/2862/)

## 初步工作量

假設：單一商店、繁體中文、一家金流、基本商品與庫存、會員音檔期限、基本管理介面與一次舊資料匯入；不含新商家審核等待時間、重新製作課程內容、訂閱制、複雜發票及物流介接。

| 工作 | 工程人日估計 |
|---|---:|
| 後台資料與權限規則盤點、匯出驗證 | 2–4 |
| 商品、購物車、訂單、基本管理介面 | 5–8 |
| 會員、音檔播放、到期授權與存取保護 | 5–8 |
| 一家金流、付款通知、付款異常與退款流程 | 4–6 |
| 舊訂單與權益匯入、整合驗收、切換 | 6–10 |
| 小計 | 22–36 |

含整合緩衝，可先抓 **25–40 工程人日**。這是工作量，不是保證的日曆交期；資料品質、現有外掛規則與人工確認可能改變估算。物流、電子發票、自動退款、分期及訂閱等需求若超出上述基礎範圍，應另估。實際開發報價、平台月費、儲存流量費與金流費率均待確認。

若先只統一入口、導覽與視覺，保留商店服務，約 2–4 工程人日；仍需維護商店 WordPress，不能當作完整移除舊系統。

## 綠界與藍新選擇

| 評估 | 延續綠界 | 改用藍新 |
|---|---|---|
| 原有商家流程 | 可延續已使用的供應商，仍需重新介接新站 | 須確認商店資格、合約及啟用條件 |
| 開發內容 | 新 API 介接、通知驗證、訂單與權限測試 | 同樣需要完整訂單及權限流程，不能省掉此部分 |
| 既有交易處理 | 可延續原供應商對帳／退款 | 舊交易仍須留在綠界處理，不能直接移到藍新退款 |
| 是否較省錢 | 未取得實際合約，不能下結論 | 同左，不能只看宣傳費率 |
| 本次建議 | 第一階段優先方案 | 如付款方式、撥款條件或實際費用更符合需求，再選擇 |

藍新有官方 API 文件下載入口，但本次未取得並核對完整現行串接版本，因此不列出未確認的參數或承諾特定功能。[藍新官方 API 文件](https://www.newebpay.com/website/Page/content/download_api)

下一個決策依據是商店後台的唯讀盤點及兩家實際方案，不是現在停用綠界。遷移時須先驗收付款成功、失敗、重複通知、延遲入帳、退款與授權到期，再安排切換；有未結清交易或有效課程權益時，先保留舊系統必要的查詢與處理能力。
